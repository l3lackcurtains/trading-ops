# Scan structure — folder layout, snapshot template, INDEX.md format

> Part of the [scan protocol](../scan-rules.md). See also: [protocol](protocol.md), [tiers](tiers.md), [data](data.md), [style](style.md).

---

## Folder structure

One folder per ticker / instrument. Macro is its own folder. Asset-class subgrouping under `scanned/`.

```
scanned/
├── INDEX.md                           ← top-level navigator (auto-generated)
├── MACRO/
│   ├── current.md                     ← active snapshot
│   ├── archive/
│   │   ├── 2026-04-29.md              ← latest snapshot per month
│   │   └── 2026-03-15.md
├── stocks/
│   ├── BBAI/
│   │   ├── current.md
│   │   ├── archive/
│   │   └── notes.md                   ← optional, freeform between scans
│   ├── NIO/
│   ├── ORCL/
│   └── ...
├── fx/
│   └── EURUSD/
├── indices/                            ← when scanning SPX, NDX, etc.
├── crypto/                             ← BTC, ETH eventually
└── SCREENS/                            ← /discover output
```

## File naming

- Asset-class folder: `scanned/<ASSET-CLASS>/` — `stocks` / `fx` / `indices` / `crypto`
- Ticker folder: `scanned/<ASSET-CLASS>/<TICKER>/` — UPPERCASE ticker (`NIO`, `EURUSD`, `BTC`)
- Top-level: `scanned/MACRO/` (regime tracker) and `scanned/SCREENS/` (discovery layer) live above the asset-class folders
- Active scan: `<ticker-folder>/current.md` (always the latest snapshot)
- Archived snapshots: `<ticker-folder>/archive/<YYYY-MM-DD>.md` (one file per snapshot)
- Notes: `<ticker-folder>/notes.md` (optional, freeform)
- Index: `scanned/INDEX.md` (auto-generated by `/scan` no-args mode)
- Screens: `scanned/SCREENS/` — protocol lives in [`guide/discover-rules.md`](../discover-rules.md), not here

## Snapshot structure (every `current.md` and archived snapshot)

1. **Header** — plain markdown title `# <TICKER> — <Long Name>` then `## Snapshot — YYYY-MM-DD (DayOfWeek)` followed by a bulleted vitals block:
   - Price (with day change % and timestamp)
   - Market cap · float · shares out · avg vol · beta
   - 52W range with anchored date for ATL/ATH
   - Sector / Industry
   - Regime (one-line read of the macro regime)
   - Next catalyst (date + 🔥 if within 7 days)
   - **Coverage tier:** line — canonical format `**Coverage tier:** Pos **X** · Swing **X** · Day **X**` parsed by `regen_index.py`

   No boxed banner — plain markdown header + bullets. Section dividers: plain `---` (not heavy `═══`).
2. **Action verdict** — required. Three components in order: (a) **per-horizon verb + pattern slug + 1-line trigger spec**, (b) **ASCII price ladder** showing all trade-relevant levels with current price marker, (c) **trade table** with structured Entry / Stop / Target1 / Target2 / Target3 / R:R / Size / Time-stop columns. Format:

   ```markdown
   ## Action — YYYY-MM-DD

   - **Pos: <VERB>** *(pattern: `<slug>`)* — <1-line trigger spec>
   - **Swing: <VERB>** *(pattern: `<slug>`)* — <trigger spec>
   - **Day: <VERB>** *(pattern: `<slug>`)* — <trigger spec>

   ### Price ladder

   ```text
                <TICKER>  -  YYYY-MM-DD  -  spot $X (intraday)
                ===================================================

                UPSIDE  (bull resolution path)
      $XX,XXX  ===  [T2] <annotation>
      $XX,XXX  ===  [T1] <annotation>
      $XX,XXX       --> LONG entry
      $XX,XXX  ===   ^^ trigger: <condition>
      $XX,XXX  ###  <zone or context>
      - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
      $XX,XXX       --> DAY SHORT entry  (or other intraday plan)
      $XX,XXX  -X-  STOP
   >> $XX,XXX  ***  CURRENT  ***
      $XX,XXX  ===  [t] day target / opportunistic
      - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
                DOWNSIDE  (bear resolution path)
      $XX,XXX  ===   vv trigger: <condition>
      $XX,XXX       --> SHORT entry
      $XX,XXX  -X-  STOP
      $XX,XXX  ===  [T1] <annotation>
      $XX,XXX  ===  [T2] <annotation>
      $XX,XXX  ===  [T3] <annotation>
   ```

   ### Trade table

   | Plan | Side | Trigger | Entry | Stop | T1 | T2 | T3 | R:R (T1/T2/T3) | Size | Time stop |
   |---|---|---|---|---|---|---|---|---|---|---|
   | Swing-A | SHORT | <condition> | $X | $X | $X | $X | $X | x.x / x.x / x.x | full/half/quarter | YYYY-MM-DD |
   | Swing-B | LONG | <condition> | $X | $X | $X | — | — | x.x | half | YYYY-MM-DD |
   | Day-A | SHORT | <condition> | $X | $X | $X | — | — | x.x | full | YYYY-MM-DD close |
   | Pos | WAIT | — | — | — | — | — | — | — | — | — |
   ```

   **Verbs:** **LONG** / **SHORT** / **HOLD** / **ADD** / **TRIM** / **HEDGE** / **CALL** / **PUT** / **WAIT** / **N/A**. Pattern slugs are short kebab-case tags describing the setup (e.g. `earnings-binary-call`, `range-breakout`, `failed-bounce-short`); use a consistent vocabulary across scans so cross-ticker hit rates can be aggregated. Two-sided WAIT triggers cite both possible resolution patterns inline.

   **Ladder conventions:**
   - Wrap in a fenced ` ```text` block so monospace alignment renders.
   - Prices descend top→bottom (highest at top, like a real price chart).
   - Use only ASCII characters (no emojis, no unicode bullets) — `===` for level lines, `>>` to mark current price, `-->` for entry, `-X-` for stop, `[T1/T2/T3]` for targets, `[t]` for day target, `^^` `vv` for triggers, `###` for zones, `***` to flag the current-price row.
   - Insert a `- - -` divider between upside and downside sections.
   - Maximum ladder height: ~20 rows. If more levels exist, drop the least-actionable.

   **Trade table conventions:**
   - One row per actionable plan (Swing-A, Swing-B, Day-A, Day-B, Pos). Plans with no setup get a single WAIT row with all dashes.
   - R:R = (T_n − Entry) ÷ (Entry − Stop) for longs; (Entry − T_n) ÷ (Stop − Entry) for shorts. Round to 1 decimal.
   - Time stop column: absolute date for swings (entry + 15d), `YYYY-MM-DD close` for day-trades, `—` for WAIT/HOLD.
   - Skip targets that don't exist (`—` not `0`).
3. **TL;DR** — 3–5 bullets: framework verdict, current bias, key risks. If a `Δ` marker applies, it goes here as the first line.
4. **Prior-scan track record** — required when `archive/` has ≥1 snapshot. Read the most recent archived snapshot's Action verdict + trigger spec; compare to today's price/state; mark each prior call as **tracked** (call valid, trigger pending or fired correctly), **fired** (trigger hit and position would be in profit/loss as predicted), **invalidated** (trigger negated by price action — e.g., we said "short below $X" and price never went there before reversing), or **stale** (>14 days since trigger spec, no resolution). One row per prior horizon-call, max 5 rows. Skip the section on first scans.
5. **Body sections** — varies by scan type (6-pillar fundamentals for stocks, asset-class flow & positioning per the relevant flow doc, technical read, news & analyst context). Stock scans pull from [scorecard.md](scorecard.md) + [data.md](data.md); non-stock scans pull from the matching flow doc ([crypto-flow.md](crypto-flow.md) / [index-flow.md](index-flow.md) / [fx-flow.md](fx-flow.md) / [commodity-flow.md](commodity-flow.md)). The technical-read section uses [Volume Profile](../../docs/volume-profile.md) + [VWAP](../../docs/vwap.md) — POC / VAH / VAL / HVN / LVN levels and session/weekly/monthly/quarterly/anchored VWAP with ±σ bands; numeric layer pre-computed by `scripts/fetch_ohlc.py`.
6. **Sources** — every external claim cited with markdown links

`current.md` does **NOT** contain an Archive section — archives live in their own files under `archive/`.

## ASCII visualizations — only where they show something tables can't

The default expression for structured data in scans is **markdown tables and bullets**. ASCII art is reserved for sections where the visual conveys **geometry or directional relationships** that don't fit a table. Two places earn it:

1. **Price ladder** (Action verdict, required) — see top of this file. The 1D vertical price layout with labeled levels is unique to ASCII; tables can't show "what's between $X and $Y" the same way.

2. **Force diagram** (Flow → trade decision section) — vertical arrows showing directional forces stacking with a target marker. Skip when the flow signal is neutral (no net force).

   ```text
      Force diagram — net direction into <OPEX or catalyst>:

            spot $X.XX
                 ●
                 │
                 ▼  ▼  ▼  gamma pull (max pain $Y.YY)
                 ▼  ▼  ▼  dealer hedge direction (P/C X.XX read)
                 ▼  ▼  ▼  dark-pool venue read (XX% vs 30d avg)
                 │
                 ▽
            $Y.YY ──── target by <date>

            <squeeze-tier read>
            → <one-line direction call>
   ```

   Use `▼` for downward forces, `▲` for upward; `▽` `△` for the target marker. Add additional force lines only if SI / FTD / borrow create a meaningful divergence or amplification.

### Sections that should NOT use ASCII art

These use markdown tables / bullets / plain text — ASCII would just duplicate without adding signal:

- **Header / vitals** — plain markdown header + bullet list (no boxed banner)
- **6-Pillar aggregate summary** — single line: `**Aggregate:** PASS **N** · NEUTRAL **N** · FAIL **N** → **N/6**`. The per-pillar table below carries the detail.
- **Auto-reject gate check** — markdown table (Gate / Threshold / Reading / Fires?)
- **High-conviction confirmation** — markdown table (Test / Result)
- **Per-TF EMA values** — markdown table (EMA / Value / Slope / Δ vs price). Optionally followed by a one-line summary of EMA posture + price-position.
- **Regime fit** — markdown table (Horizon / Lean / Reason)
- **Pre-print scenario tree** — markdown table (Print outcome / Read / Expected reaction)
- **Verdict per horizon** — single markdown table (Horizon / Tier / Verb / Dominant / Upgrade / Downgrade)
- **Section dividers** — plain `---`, not heavy `═══`

### Principle

Every ASCII block must answer a question a table can't. Price ladder shows level relationships in 1D space. Force diagram shows directional vectors. Everything else — verdicts, scorecards, EMA tables, gate checks, scenario trees — uses markdown tables.

## Snapshot dating

- Every snapshot leads with `## Snapshot — YYYY-MM-DD (DayOfWeek)`
- Date is the **scan date**, not the publish date of the underlying data
- Convert relative dates ("today", "last week") to absolute when writing

## Δ marker (material change)

When a rescan changes the verdict, regime, aggregate score, or key technical state, prepend the new TL;DR with one line:

```
**Δ since last scan (YYYY-MM-DD):** <what changed>
```

Examples:
- `Regime: Goldilocks → Stagflation`
- `Verdict: Watchlist (3/6) → Buy (5/6) after Q2 earnings confirmation`
- `Technical: counter-trend rally at descending 200d → 200d turning flat, base forming`
- `Tier: Pos S / Swing B → Pos S / Swing W (recovery confirmed)`

## Notes file (optional)

`<ticker-folder>/notes.md` is for freeform observations between formal scans — quick price-action notes, news mentions, "watch this level" reminders. Not part of any auto-generated structure. Persists between rescans.

## INDEX.md format

Auto-generated by `/scan` with no args. Structured as a coverage report with one master coverage table (3-tier columns per horizon), plus catalyst monitor, coverage change log, performance log.

**Sections (in order):**

1. **Header** — last-regenerated date, current macro regime link, coverage-universe summary stats (e.g. `8 names · 6 stocks · positional active: 2 / swing active: 3 / day active: 0`)
2. **Coverage tiers legend** — short reference for the 5 tier letters + 3 horizons (mirror of [tiers](tiers.md))
3. **Master coverage table** — one row per stock, columns:
   `Ticker · Pos · Swing · Day · Score · Last Scan · Best near-term trigger · Next Catalyst`
   The 3 tier columns each show the horizon's letter (**T** / **W** / **B** / **S** / `—`). Sort: rows with at least one **T** first, then rows with at least one **W**, then **B**, then all-**S**, then **X**. Within group, sort by last-scan date desc.
4. **Per-horizon focus blocks** — three small tables surfacing actionables per horizon:
   - **Positional Top Picks + Watchlist** — names where Pos column is **T** or **W**, with positional-specific trigger
   - **Swing Top Picks + Watchlist** — names where Swing column is **T** or **W**, with swing-specific trigger
   - **Day-trade Top Picks + Watchlist** — names where Day column is **T** or **W**, with intraday-specific trigger
   Empty tables read "None currently — wait IS a position." Don't pad.
5. **X Dropped** — persistent rows (never deleted) of names removed from coverage with date + reason
6. **Macro / Indices / FX / Crypto** — separate table for non-stock instruments: `Ticker · Pos · Swing · Day · Last Scan · Regime / Bias · Notes`. Same tier columns as the master table — tradeable instruments (BTCUSDT, EURUSD, GLD, etc.) populate them; pure regime trackers (MACRO) use `—` across all three.
7. **Catalyst monitor — next 30 days** — sorted by date (NOT ticker), columns: `Date · Ticker · Pos · Swing · Day · Event`. 🔥 marker on dates within 7 days. The 3 tier columns make it obvious at a glance which horizons are live around the catalyst.
8. **Coverage changes — last 30 days** — newest first, columns: `Date · Ticker · Horizon · Action · Tier change · Reason`. Horizon ∈ {Pos, Swing, Day, All}. Actions: `Initiated` / `Upgraded` / `Downgraded` / `Dropped` / `Suspended`. Tier-change column shows `prior → new` with tier letters. A single rescan can produce multiple rows (one per horizon that changed).
9. **Performance / audit log** — append on rescans when a prior trigger fires (or fails). Format: `YYYY-MM-DD <TICKER> [horizon]: prior trigger "<spec>" → outcome "<what happened>". Verdict tracked / missed.` Empty until first rescan after this index version.
10. **Recent screens** — `/discover` outputs (preserved from prior format)
11. **Legend footer** — `⚠ stale (> 14 days)` · `🔥 catalyst within 7 days`

**Rules:**
- Master coverage table rows are computed from each `current.md`'s `**Coverage tier:**` header line — INDEX.md is a roll-up, not a separate source of truth.
- **X** Dropped rows are written manually into INDEX.md once and persist; they don't depend on a `current.md` (the folder may have been deleted).
- The Catalyst monitor pulls "Next catalyst" from each `current.md` plus MACRO catalysts.
- The Coverage changes log only adds entries on tier transitions, **per horizon**. A rescan that confirms the same Pos/Swing/Day tier doesn't add a row.
- Mark ⚠ on rows where last-scan > 14 days old.
- Mark 🔥 on catalyst dates within 7 days.
- The `INDEX.md` regeneration command is `/scan` with no args, or run `scripts/regen-index.py` directly.
